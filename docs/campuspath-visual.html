CampusPath V4.1
HKUST × Google Hackathon · Gemini Enterprise for Higher Education

把学生想成为的人，
倒推成今天能走的一步。

CampusPath 是一套从入学陪伴到毕业的长期 AI Agent 系统。它连接学生授权的成长档案、教务系统、 LMS、课程目录、个人日历与校内外机会，把碎片化的资源组织成多时间尺度、可执行、 随变化实时校准且不过载的校园成长路径。

一句话定位（原文引用）
持续整合校内外可信资源与学生真实反馈，把学生想成为的人动态倒推成当下可执行、并随变化实时校准的校园成长路径。

01 · 为什么要做这个项目

真实问题不是「没有资源」，而是资源无法变成路径

大学里的课程、比赛、实验室、交换、讲座、社团、创业支持和职业机会很多，但高度碎片化。 学生一边完成繁重学业，一边还要长期搜索、验证、判断、规划和追踪这些资源，认知成本非常高。 很多机会并非学生能力不足而错过，而是因为发现太晚、无法判断资格、不知道如何组合，或计划与现实精力不匹配。

本项目要降低的六类长期成本

COST 1
发现成本
不知道有哪些可信机会
COST 2
理解成本
看到了，却不知道具体资格与价值
COST 3
规划成本
不知道课程、经历和机会如何形成有依赖关系的路径
COST 4
执行成本
收藏很多，但没有转成行动、材料和日历
COST 5
纠偏成本
做完没有沉淀，系统下次仍重复安排无效或不适合的事情
COST 6
容量管理成本
不知道课程、生活和成长任务如何排进真实日历，容易冲突、过载或挤压休息
为什么不能只做一次职业规划： 学生的能力、目标、精力和外部机会都在变化。大一时暂时不符合的实习，大三可能正好合格；原本感兴趣的方向， 经过一次实践可能发现并不适合。因此真正有用的产品不是给出一张静态路线图， 而是建立一个能够持续感知、记忆、验证和重规划的成长系统。
02 · 项目目的与最终产品定位

一个校园成长操作系统，不是又一个职位聚合网站

最终产品定位（原文引用）
一个由 Gemini Enterprise 驱动、以学生自主选择为中心的动态校园成长操作系统：把长期方向转化为近期行动，把真实行动转化为证据与记忆，再用这些新证据持续校准下一阶段路径。
Spec V4.1 · §2.1

系统的核心闭环

Profile + Education + Calendar/Capacity State→ Goal→Requirement→Gap→ Course & Opportunity→Constraint-safe Plan→ Consent-based Action→Reflection & Evidence→ Confirmed Profile/Memory Update→Replan

双边价值：学生得到什么，学校得到什么

命题是 Gemini Enterprise for Higher Education，实际部署与付费方是大学。因此产品必须同时成立两个价值主张。

FOR STUDENTS
把长期方向倒推成当下可执行、且不挤压生活的路径
每一条建议都说明补什么差距、形成什么证据、为什么是现在。
FOR THE UNIVERSITY
让已投入巨大成本的资源变成可测量、可改进、可归因的成长资产
并第一次让学校看到「我们的资源池覆盖不了学生的哪些真实需求」。
关于「学校资源」的口径： 凡是因为学生的在校身份而能够获得的机会，都算学校资源。校友内推、企业来校招聘、合作方名额、跨校联盟活动， 本质上都是学校品牌与关系网带来的，不因为主办方在校外就不算。因此本产品不区分校内 / 校外资源， 只区分学生是否发现、是否够格、是否用上。
03 · 项目针对的人群

五类目标导向人群，不是五种身份标签

这五类是按学生「想走向哪里」划分的目标导向人群，不是按本科、硕士、博士或国籍划分，也不是给学生永久贴标签。 一个学生可以同时拥有两个候选方向，并随着实践改变权重。

MODE 1
就业与职业发展
进入目标企业、行业、岗位或公共服务领域
系统重点：岗位要求、技能证据、项目、实习、作品、人脉与招聘节奏
MODE 2
学术与深造
读研、读博、进入研究领域、寻找导师
系统重点：课程基础、研究方法、实验室、论文阅读、科研经历、推荐信与申请时间线
MODE 3
创业与创新
创办项目、验证需求、加入孵化器或组建团队
系统重点：问题发现、技术/商业能力、比赛、原型、用户验证、导师、资金与团队
MODE 4
兴趣与个人成长
艺术、体育、语言、公益、创作或其他长期兴趣
系统重点：能力成长、社群、作品、体验质量与可持续投入，不强迫职业化
MODE 5
探索与方向未定
暂时迷茫，希望通过实践逐步认识自己
系统重点：低成本、多样化的探索实验；用实际体验更新兴趣与目标信心
横向约束，不是第六类人
Context Pack
国际身份、经济条件、照护责任、健康与精力、通勤、语言、无障碍需求
作为每一种发展模式都必须尊重的个人约束注入，而不是复制一套新的 Agent

04 · 边界

本产品不是什么

明确的否定项与功能清单同等重要 —— 它们决定了哪些实现路径从一开始就被排除。

  • ×不是保证进入某家公司或学校的「成功预测器」
  • ×不是替学生做不可逆人生决定的自动决策系统
  • ×不是用活动数量、忙碌程度或简历长度衡量成长的系统
  • ×不是未经授权抓取个人或平台数据的监控工具
  • ×不是学校用来查看学生私人想法或控制学生选择的工具
  • ×不是医疗器械、心理诊断工具或自杀风险预测系统
  • ×不是仅凭日历空档、作息安排或运动时长就向学校报告学生的监控系统

06 · Agent 体系

6 个语义 Agent、2 个 Runtime、9 个确定性服务

设计原则：不要把每个函数都包装成 Agent。需要独立目标、语义判断、工具或状态的模块才使用 Agent； 日期比较、资格规则、去重、容量校验和评分等可重复逻辑尽量由确定性代码完成。

V4.1 的核心架构原则：A5 是系统中唯一做取舍（trade-off）的 Agent。 A1 / A2 / A3 / A4 只负责把事实与候选整理清楚，不做排序。这让「为什么推荐这个」只有一个解释来源， 也让每个 Agent 的输出契约可以独立评测。

ADK Workflow Agent 的三处使用

这些都是 Agent 内部的工作流构件，不是新的部署单元：Agent 总数仍为 6，Runtime 仍为 2， Registry 与 Gateway 的治理对象数量不变。

S1 · ParallelAgent
A5 内部：Plan A/B/C 并行生成
Balanced / Ambitious / Low-load 在三套不同强度约束下并行生成，每套方案获得独立且专注的推理，耗时不叠加。
实现 F12
S2 · LoopAgent
A5 内部：约束修复循环
生成计划 → Rules 校验 → 违反容量、保护区块或先修则带着违规原因重生成（最多 3 轮）。

S3 · ParallelAgent
A4 内部：多源隔离抽取
多个来源并行抽取，且每个来源的不可信内容被隔离在独立子上下文中 —— 一个来源的注入无法污染另一个来源。
实现 F09，同时是安全措施
08 · Agent 安全契约

把隐私从「提示词写得小心」提升为「架构上做不到」

以下四条不是设计建议，而是部署契约：每一条都有对应的自动化测试，测试不通过则构建失败。

§8.9.1
A4 不可信内容隔离
① 外部文本一律以 user-role 数据块传入并加边界标记，永不拼接进 system prompt；
② 工具白名单只有 read_source 与 emit_opportunity_draft —— 没有学生数据读取、没有发布权、没有出网写；
③ 输出必须通过确定性 Schema 闸门后才进审核队列，失败即丢弃，不回喂给 LLM 重试。
威胁模型结论：即使 A4 被完全劫持，攻击者能造成的最大影响是「提交一条会被人工审核拒绝的草稿」
§8.9.2
A1 输出类型边界
A1 同时接触学生最私密的 Reflection 原文与最终流向校方的质量信号。 它向 Aggregation Service 的输出只能是结构化 EventQualityFeedback，接口类型上不接受自由文本； 且 A1 没有任何写入聚合数据域的工具权限。
Private Reflection Exposure = 0 由数据类型边界 + 工具权限边界共同保证
§8.9.3
A5 的 validation_id 强制绑定
Rules 每次校验返回一个 validation_id；A5 输出的每一个 PlanItem、每一条资格结论必须携带对应 ID； API 层拒绝任何缺失或伪造的输出。
保证资格、先修、截止、容量、保护区块的判定不可能被模型输出覆盖
§8.9.4
Wellbeing 链路零 LLM
五类信号判定、提醒文案、outreach 邮件内容全部由确定性代码与固定模板生成。 理由：这五类判定是纯阈值比较，不存在语义判断，引入 LLM 不增加能力、只增加幻觉风险 —— 而这是全产品风险最高的数据类别。
唯一允许的 LLM 是 A5 生成低负荷替代计划，且仍受 validation_id 约束

系统可以说什么，不能说什么： 日历没有留出 7 小时睡眠窗口 → 可以说「计划可能挤压了建议睡眠机会」，不能说「你实际只睡了 X 小时」。 连续超载、反复延期或拒绝计划 → 可以说「当前计划强度可能不合适」，不能说「你有自杀风险」。 成人参考线（7 小时睡眠、每周 150–300 分钟中等强度活动）只用于形成一般健康提示， 不是抑郁或自杀风险阈值，也不能单独触发学校报警。

16 · 量化指标

北极星指标与资源利用率刻度

北极星指标
Verified Growth Actions (VGA) / Active Student / Month

学生真实完成，且通过证据或 Reflection 证明产生技能、知识、作品、研究、人脉、机会推进或目标澄清价值的行动数量。 VGA 不奖励点击、收藏、报名或忙碌本身。

资源利用率指标

VGA 衡量的是「学生做成了多少有效行动」，但产品定位还包含「学校资源被充分利用」。这一层需要独立刻度， 否则该主张在评分中无法被检验。

指标定义证明什么
Eligible Opportunity
Discovery Rate		 一学期内学生处于 Eligible now 的资源中，学生实际看到过的比例 量化「发现成本」：有多少机会不是学生不够格，而是根本没被看见
Discovered-to-
Action Rate		 已看到且当时合格的资源中，转化为收藏 / 报名 / 加入路径 / 完成行动的比例 量化「执行成本」：系统是否把发现变成了行动，而不只是撑大收藏夹
Gap Coverage by
Available Resources		 学生 Gap Map 中的缺口，能被资源池里至少一条资源覆盖的比例 反向输出给学校的资源供给洞察 —— 一个学校今天拿不到的管理输入

这三项指标如何传导到校方

这三项指标必须到达 Career Center，否则它们只是团队自评的数字，产生不了学校侧的管理价值。 但传导方式受与活动质量反馈完全相同的隐私纪律约束：传的是全局聚合结论，不是任何学生的个体数据。 对应主架构图的 E32 / E33 两条信息流。

STAGE 1 · 个体计算
在学生私有数据域内完成
用该学生的四态资格结果、曝光记录、ActionEvent 与 Gap Map，算出一条去标识的指标元组 MetricTuple。
原始曝光与行动记录永不离开学生数据域；元组离开时已无 student_id
STAGE 2 · 匿名聚合
Aggregation Service（确定性，零 LLM）
对 MetricTuple[] 执行最小样本阈值、小样本单元抑制，产出 ResourceCoverageAggregate。
禁止低于阈值的交叉下钻，防止多重筛选把单元格缩到可识别规模
STAGE 3 · 校方呈现
Career Center Insights
全局与分组趋势视图。校方只能看到聚合结论，界面与后端都不提供任何反查个体的入口。
与 §6.7 的 Equity & Reach Insights 合流

17 · 延迟预算

延迟是设计约束，不是事后优化

多 Agent 链路若全部串行，单次交互可能达到 20–45 秒，这对交互式 Web App 与限时 Demo 都不可接受。

措施说明效果
A0 确定性路由已知意图直接分发，不经 LLM 编排覆盖约 90% 请求，省 1 次 LLM 往返
A1 / A2 / A3 并行三者之间无依赖，用 ADK ParallelAgent 同时发起3 次串行 → 1 次并行
RequirementGraph 缓存目标不变则不重算常态省去 A3
确定性服务零 LLMCapacity / Rules / Composer 三者这些环节延迟为毫秒级
会话预热学生进入应用时后台预跑至 Gap Map交互时通常只剩 A5 一跳
流式渲染先返回结构化结果骨架，解释文字后到感知延迟减半
